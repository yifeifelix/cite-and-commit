```
- **Label:** Sentence explaining it. [source]
- **Label:** Sentence explaining it. [source] [source]

## <Decision-framed heading>

<1-3 sentence paragraph, or bullets, or a table if the data is parallel.>

## <Heading that carries a judgement, e.g. "My recommendation" / "When it's a bad fit">

- **Scenario:** what to do. (uncited — this is your judgement)
- **Scenario:** what to do.

<Close: concrete offer, or the one missing input, or a bottom line.>
```

Every heading is `##`. There is no `#` and no `###` — the answer is a flat list of
sections, never a nested document.

# Bullet patterns

**Spec bullet** — label is the attribute:
> **Armrests:** 6D on the C300 versus 4D on the C100, which matters most if you type for long stretches. [source]

**Scenario bullet** — label is the user's situation:
> **On a tight budget:** take the M18; it covers the basics and you can upgrade the chair before you upgrade the desk.

**Caveat bullet** — label names the risk:
> **Not confirmed:** the M6 / M5 Pro split is supply-chain reporting, not an announced spec. [source]

**Date bullet** — label is the event:
> **Next decision:** 17 September 2026, with markets currently pricing another hold. [source]

# Table patterns

**Tier → verdict** (the most useful shape — always include a verdict column):

| Memory | Verdict | Why |
|---|---|---|
| 24GB | Tight | Runs Q4 at short context, nothing else open |
| 32GB | Minimum | Stable Q4 with an IDE running |
| 48GB | Recommended | Long context, room for Docker |
| 64GB | Overkill unless Q8 | Only worth it for higher quantisations |

**Option → who it's for:**

| Option | Price | Best for |
|---|---|---|
| A | £X | … |
| B | £Y | … |

Do not build a table where cells hold full sentences. That's a bullet list.
